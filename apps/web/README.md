# HopeNest Web (`@fundora/web`)

Next.js 14 (App Router) front end for HopeNest — Tailwind CSS, shadcn/ui components,
Lucide icons, TanStack Query, and an installable PWA shell.

## Running it

```bash
pnpm --filter @fundora/api start:dev   # API on :3000
pnpm --filter @fundora/web dev         # web on :3001
```

Open http://localhost:3001.

## How the front end talks to the API

The API sets **HttpOnly** auth cookies, which JavaScript cannot read by design. Rather than
copying tokens into `localStorage`, `next.config.mjs` rewrites `/api/v1/*` to the API origin:

```js
async rewrites() {
  return [{ source: '/api/v1/:path*', destination: `${API_ORIGIN}/api/v1/:path*` }];
}
```

Every request is therefore **same-origin**, so the browser attaches the auth cookies
automatically and the API needs no CORS allowance. Set `API_ORIGIN` per environment
(default `http://localhost:3000`).

## PWA

`next-pwa` generates the service worker into `public/` at build time (disabled in dev so a
cached shell never shadows your edits). `public/manifest.json` declares `display: standalone`,
a `#002B66` background and a `#00A86B` theme.

`<PwaInstallButton />` captures the Chromium `beforeinstallprompt` event for a one-tap
install. iOS Safari never fires that event, so it instead opens a **Share → Add to Home
Screen** walkthrough rather than a dead button. The button hides itself once the app is
already running standalone.

Icons in `public/icons/` were generated by a script; regenerate or replace them with real
brand artwork before launch.

| `/dashboard/campaigns` | The signed-in user's campaigns and KYC status |

## Deliberate decisions worth knowing

**There is no card-number form.** The card tab starts a payment intent and hands off to the
processor's hosted page (that is what `clientSecret` is for). Collecting raw PANs in our own
form would pull the whole platform into PCI-DSS scope. Wire Stripe Elements or Checkout into
`DonationHandoff` when the publishable key is configured.

**The 8% withdrawal fee shown in the UI is a preview only.** `src/lib/fees.ts` mirrors
`apps/api/src/ledger/fees.ts` using integer minor units so `gross === fee + net` exactly, but
the server recomputes the authoritative split. Keep the two files in step.

**Campaign covers use plain `<img>`,** not `next/image`. Covers are arbitrary user-supplied
URLs, and pointing the image optimizer at an open host allowlist is an SSRF-shaped risk.
Switch to `next/image` with a narrow `remotePatterns` once media is served from a known CDN.

## Live data

Every screen reads from the API — there are no fixtures and no fallback data. When a request
fails the UI says so plainly rather than showing invented numbers.

| Screen | Endpoint |
| --- | --- |
| Hero stats ticker | `GET /api/v1/stats/platform?currency=USD` |
| Discovery grid | `GET /api/v1/campaigns` |
| Campaign page | `GET /api/v1/campaigns/:slug`, `…/:id/updates`, `/payments/history/:id` |
| Fundraiser dashboard | `GET /api/v1/campaigns/id/:id` (owner/finance only) |
| Post update | `POST /api/v1/campaigns/:id/updates` |

**Currency totals are never converted.** `GET /stats/platform` reports `totalRaised` in one
`reportingCurrency` and lists everything else under `totalRaisedByCurrency`, because the API
holds no FX rates. The ticker names the other currencies instead of adding them in — summing
UGX into USD would be wrong by roughly three orders of magnitude.

**`raisedAmount` is gross settled donations, not the wallet balance.** The wallet is net of
platform and processing fees, so the two figures legitimately differ; the dashboard shows both
(`Total raised` vs `Cleared balance`).

**Campaigns without a `coverImageUrl`** fall back to a branded gradient tile bearing the
campaign title, so a missing image never renders as an empty grey box.
